# WWF — Weekend Wave Finder

> 전국 **62개 서핑 스팟**의 **16일 파도 예보**를 "이번 주말 언제 들어가지?" 한 가지 질문에 맞춰
> 다시 짠 서핑 예보 대시보드.

**🔗 [wwf.forges.work](https://wwf.forges.work)**

---

## 왜 만들었나

기존 서핑 예보 서비스는 데이터는 많은데 **정작 결정을 못 도와줍니다.**

- 파고·주기·풍향 숫자를 나열해 놓고 좋고 나쁨은 알아서 판단하라고 합니다.
- 풍향을 나침반 방위(`SSE`, `270°`)로만 보여줍니다. 그런데 오프쇼어인지 아닌지는
  **해변이 어느 쪽을 보느냐에 따라 완전히 다릅니다.** 방위만 봐서는 알 수 없습니다.
- 하루를 하나의 값으로 뭉갭니다. 실제로는 같은 날에도 오전 육풍과 오후 해풍으로
  컨디션이 완전히 갈립니다.

WWF 는 그 세 가지를 정면으로 다룹니다.

## 핵심 기능

### 🌊 16일 파도 스트립 — 메인 컨트롤
화면 최상단의 가로 스트립에서 날짜를 고르면 **아래 모든 정보가 그 날짜로 바뀝니다.**
각 날짜 카드는 파고 범위 · 3단계 판정 · 날씨 · 기온 · 강수확률 · 아침/낮/오후 바람을
104px 안에 담습니다.

### 🟢 좋음 / 평범 / 나쁨 — 색만으로 말하지 않습니다
판정은 언제나 **세 채널**로 동시에 나갑니다.

| 판정 | 색 | 도형 | 라벨 |
|---|---|---|---|
| 좋음 (60점~) | 초록 | 꽉 찬 원 ● | "좋음" |
| 평범 (38~59) | 앰버 | 마름모 ◆ | "평범" |
| 나쁨 (~37) | 로즈 | 납작한 막대 ▬ | "나쁨" |

색맹이거나 흑백으로 출력해도 도형과 한글 라벨이 남습니다.

### 🧭 해변 단면 바람 다이어그램
나침반을 버렸습니다. **위쪽은 언제나 육지(해변), 아래쪽은 언제나 바다.**
화살표가 바다 쪽을 향하면 오프쇼어(좋음), 해변 쪽을 향하면 온쇼어(나쁨).

```
   ┌─────────┐
   │ 🏖 해변  │
   ├────↓────┤   화살표가 바다로 = 오프쇼어 = 파도 면이 세워짐
   │ 🌊 바다  │
   └─────────┘
```

스팟이 바뀌어도 그림의 의미가 고정되므로, 방위를 몰라도 읽힙니다.
(양양은 서풍이 오프쇼어, 만리포는 동풍이 오프쇼어입니다 — 앱이 스팟별로 알아서 계산합니다.)

### 📍 전국 62개 스팟 — 동해 33 · 남해 8 · 제주 15 · 서해 6
양양·강릉·포항 같은 주력 권역은 물론, 설악·정암(리버마우스)·대진처럼 로컬만 아는
스팟과 고흥 남열·제주 월령 같은 외곽까지 넣었습니다. 스팟 목록은
[`src/data/koreaSurfSpots.ts`](src/data/koreaSurfSpots.ts) 한 파일에 모여 있고,
`npm run verify:spots` 가 좌표·방위를 실측 검증합니다.

### 🧾 스팟 가이드 — 예보 수치로는 알 수 없는 것
파고와 바람은 "오늘 파도가 어떤가"만 답합니다. 스팟마다 다음을 함께 답니다.

| 축 | 예 |
|---|---|
| 실력대 | 입문 가능 / 중급 이상 / 상급자 |
| 바닥 | 모래 · 리프 · 포인트 |
| 시즌 | 가을·겨울 / 여름·가을 / 겨울·봄 |
| 물때 | 물때 무관 / 중조 / 만조 전후 |
| 붐빔 | 한산 / 보통 / 붐빔 |
| 위험 요소 | 얕은 리프·성게 / 방파제 테트라포드 / 조차 큼 … |

서해는 조차가 6~9m라 **물때가 사실상 입수 가능 시간을 정합니다.** 동해는 30cm라
거의 무관합니다 — 같은 "파고 0.8m"도 해변에 따라 의미가 전혀 다릅니다.

### ⏱️ 예보 정확도를 숨기지 않습니다
16일을 전부 같은 톤으로 보여 주면 사용자가 2주 뒤 계획을 그대로 믿게 됩니다.

| 구간 | 표시 |
|---|---|
| D+0~2 | 그대로 |
| D+3~6 | 그대로 |
| D+7~ | 카드 테두리가 **점선**, `≈` 표시 — 추세 참고용 |

**조위는 모델이 약 9일치만 줍니다.** 하지만 조석은 기상이 아니라 **천문 현상**이라
연장 계산이 가능합니다 — 받아 온 구간에 조석 상수를 맞춰(조화분해) 나머지를 예측하고,
그 구간은 곡선을 **점선**으로 그리고 "조화분해 예측값"이라고 명시합니다.

실측 검증(앞 2/3 학습 → 뒤 1/3 예측): **만조·간조 시각 오차 평균 30분~1시간.**
조석이 지배적이지 않은 동해(조차 40cm 남짓)에서는 적합이 스스로 거부되고
"조위 예보 범위 밖"으로 표시됩니다 — 틀린 조위는 없는 것보다 나쁩니다.

파고·주기는 두 모델(`best_match` → `ncep_gfswave025`)을 이어 붙여 16일까지 실제 값을 씁니다.

### 🗺️ 지도 · 물때 · 시간별 상세
- OpenStreetMap 기반 인터랙티브 지도에서 스팟 전환 (전국 뷰에서는 점, 확대하면 이름표)
- Open-Meteo `sea_level_height_msl` 기반 실제 조위 곡선 (만조·간조 극점 직접 라벨)
- 시간별 날씨·기온·강수확률·파고·주기·에너지·바람·물때·스코어

### 🎨 테마 3종
`Sea Glass`(기본) · `Golden Hour` · `Night Swell`.
모든 테마가 3개 표면에서 WCAG AA(4.5:1)를 만족하도록 대비를 계산해 검증했습니다.

## 서프 스코어 — 곱셈 모델

`utils/surfScoreEngine.ts`

```
점수 = 크기(너울 파고) × 주기계수 × 방위 × 차폐 × 바람 × 지저분함 × 조석
```

**덧셈이 아니라 곱셈입니다.** 예전엔 `에너지 40 + 주기 25 + 바람 35` 로 더했는데,
그러면 탈 파도가 없어도 바람만 좋으면 80점이 나옵니다. 실제로 그런 일이 있었습니다
(아래 실측). 바람은 파도를 만들지 않습니다 — 있는 파도의 면을 다듬거나 망칠 뿐이라
곱셈 필터가 맞습니다. 주요 예보 서비스도 바람·조석을 곱셈으로 씁니다.

### 🔑 주기가 지배합니다

```
L₀ = 1.56 × T²          심해 파장
해저 감지수심 = L₀ / 2
```

| 주기 | 파장 | 감지수심 | 성격 |
|---|---|---|---|
| 5초 | 39m | 20m | **풍파** — 해변 코앞에서 급히 서고 즉시 붕괴 |
| 7초 | 76m | 38m | 풍파 |
| 10초 | 156m | 78m | **그라운드 스웰** |
| 16초 | 399m | 200m | 그라운드 스웰 (극도로 정돈) |

**점수는 전체 파고/파주기가 아니라 `swell_wave_height`/`swell_wave_period` 로 계산합니다.**
전체값에는 풍파가 섞여 있어, 못 타는 4.8초짜리가 6.5초로 보고됩니다.

### ● Solid / ○ Open — 크기와 질은 다릅니다

surf-forecast 방식. **Solid**(●)는 주기 10초 이상 + 오프쇼어/무풍일 때만.
그 외에는 점수가 높아도 **Open**(○) — "파고는 나오는데 탈 물건은 아님".

### 실측으로 보정했습니다

2026-08-30 고성·속초·양양 4곳 현장 확인. 예전 엔진이 70~80점을 준 날의 실제 바다는
장판·코앞붕괴·챠피였습니다. 그날 너울 주기는 **4.8초**.

| 스팟 | 이전 | 현재 | 현장에서 본 것 |
|---|---|---|---|
| 천진 | 80 | **1** | 파도 한 점 없는 장판 |
| 봉수대 | 78 | **9** | 코앞에서 컬 → 즉시 붕괴, 될까 싶은 수준 |
| 설악 | 72 | **8** | 매우 챠피·지저분 |
| 물치 | 70 | **8** | 그럭저럭 (가본 곳 중 최선) |

> ⚠️ 오른쪽 열은 **서술이지 점수가 아닙니다.** 현장에서 파도를 0~100 으로 매기는 일은
> 없고, 매겨도 척도가 다릅니다. 관측을 숫자로 바꿔 놓고 그 숫자로 모델을 채점하면
> 자기가 만든 답안지로 채점하는 꼴이 됩니다. 기록은
> [`src/data/fieldReports.ts`](src/data/fieldReports.ts) 에 **서술 그대로** 남깁니다.

설악·물치는 **같은 9km 격자**라 모델 입력이 동일합니다. 8점으로 같게 나오는 건
"구분할 정보가 없다"는 뜻이고, 그렇게 두는 게 정직합니다.

### 급경사도 — "크지만 못 타는 파도"

```
급경사도 = H₀ / L₀ = H₀ / (1.56 × T²)
```

**같은 주기라면 파고가 클수록 오히려 나빠집니다.** 파형이 가팔라져 면이 서기 전에
마루가 무너지기 때문입니다(클로즈아웃).

| 파고 | 5초 | 12초 |
|---|---|---|
| 0.6m | 12점 | 54점 |
| 1.2m | 10점 | 85점 |
| 2.0m | **8점** | **100점** |

이 항이 없었을 때 봉수대(1.0m)가 설악(0.9m)보다 높게 나왔습니다 — 현장에서는
봉수대가 더 나빴는데도요.

## 기술 스택

| | |
|---|---|
| Frontend | React 18 + TypeScript |
| Build | Vite 5 |
| Styling | Tailwind CSS 3 + CSS 변수 `[data-theme]` 토큰 |
| Map | Leaflet + OpenStreetMap 표준 타일 (다크 테마는 CSS 필터로 반전) |
| Data | [Open-Meteo](https://open-meteo.com) Marine & Forecast API (16일 / 384시간)<br>파고: `best_match` + `ncep_gfswave025` 병합 · 조위: `best_match` 약 9일 |
| Hosting | Cloudflare Pages (`wwf.forges.work`) |

**API 키가 필요 없습니다.** Open-Meteo 는 비상업적 이용에 무료이고 키를 요구하지 않습니다.
